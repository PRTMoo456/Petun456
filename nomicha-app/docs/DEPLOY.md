# วิธีติดตั้งระบบจริง — ทำตามทีละขั้น (ไม่ต้องเขียนโค้ดเป็น)

ต้องสมัคร 3 เว็บ ฟรีทั้งหมด แต่ละเว็บทำหน้าที่ต่างกัน:

| เว็บ | ทำหน้าที่อะไร | เปรียบเทียบง่าย ๆ |
|---|---|---|
| **GitHub** | เก็บไฟล์โค้ดทั้งหมด | ตู้เก็บเอกสาร |
| **Supabase** | ฐานข้อมูล + ระบบล็อกอิน | สมุดบัญชีจริง ที่เก็บยอดทุกวัน |
| **Vercel** | ทำให้เป็นเว็บที่เปิดจากมือถือได้ | หน้าร้าน ที่ทุกคนเข้ามาดู |

**ลำดับที่ต้องทำ:** GitHub (เอาโค้ดขึ้น) → Supabase (สร้างฐานข้อมูล) → Vercel (เปิดเว็บ) → กลับมาสร้างบัญชีในแอป

ทั้งหมดใช้เวลาประมาณ 45–60 นาที ทำครั้งเดียวจบ · **แนะนำให้ทำบนคอมพิวเตอร์** (ต้องคัดลอก-วางข้อความยาว ๆ หลายรอบ ทำบนมือถือลำบาก)

> **ก่อนเริ่ม** — แตกไฟล์ `nomicha-app.zip` ที่ได้มา จะได้โฟลเดอร์ชื่อ `nomicha-app` เก็บไว้ให้หาเจอ ทุกขั้นตอนข้างล่างอ้างถึงไฟล์ในโฟลเดอร์นี้

---

## ขั้นที่ 1 — GitHub (เก็บไฟล์โค้ด)

### 1.1 สมัคร
1. ไปที่ https://github.com → กด **Sign up**
2. กรอกอีเมล ตั้งรหัสผ่าน ตั้งชื่อผู้ใช้ (จะกลายเป็นชื่อในลิงก์ เช่น `phurithat`)
3. ยืนยันอีเมลตามที่ GitHub ส่งไปให้

### 1.2 สร้างที่เก็บโค้ด (repository)
1. มุมขวาบน กด **+** → **New repository**
2. **Repository name** ใส่ `nomicha-app`
3. เลือก **Private** (สำคัญ — ไม่งั้นคนอื่นเห็นโค้ดร้านเราได้)
4. **อย่าติ๊ก** "Add a README file" หรืออะไรทั้งนั้น ปล่อยว่างไว้
5. กด **Create repository**

### 1.3 อัปโหลดไฟล์ (ลากวางได้เลย ไม่ต้องลงโปรแกรม)
1. หน้าที่ขึ้นมาหลังสร้าง repo จะมีลิงก์ **uploading an existing file** — กดตรงนั้น
   (ถ้าหาไม่เจอ: กดแท็บ **Add file** → **Upload files**)
2. เปิดโฟลเดอร์ `nomicha-app` ที่แตกไฟล์ไว้
3. **เลือกทุกอย่างที่อยู่ "ข้างใน" โฟลเดอร์** (กด Ctrl+A บน Windows / Cmd+A บน Mac) แล้วลากมาวางในหน้าเว็บ
   ⚠ **ลากของข้างในเข้าไป ไม่ใช่ลากตัวโฟลเดอร์ทั้งอัน** — ถ้าลากทั้งโฟลเดอร์ Vercel จะหาไฟล์ไม่เจอในขั้นที่ 3
4. รอจนอัปโหลดครบ (เห็นรายชื่อไฟล์ขึ้นมาเต็มหน้า) แล้วกด **Commit changes**

**เช็คว่าถูกต้อง:** หน้า repo ต้องเห็นไฟล์ `package.json` และ `index.html` **อยู่หน้าแรกเลย** ไม่ต้องกดเข้าโฟลเดอร์ก่อน
ถ้าเห็นแค่โฟลเดอร์ `nomicha-app` อันเดียว แปลว่าลากผิด — กดเข้าไปในโฟลเดอร์นั้น เลือกไฟล์ทั้งหมด ลบทิ้ง แล้วอัปโหลดใหม่ตามข้อ 3

## ขั้นที่ 2 — Supabase (ฐานข้อมูล + ระบบล็อกอิน)

### 2.1 สมัครและสร้างโปรเจกต์
1. ไปที่ https://supabase.com → **Start your project** → เลือก **Continue with GitHub** (ใช้บัญชี GitHub ที่เพิ่งสมัคร จะได้ไม่ต้องจำรหัสเพิ่ม)
2. กด **New project**
3. **Name** ใส่ `nomicha`
4. **Database Password** — กดปุ่มสุ่มให้ก็ได้ แล้ว **คัดลอกเก็บไว้ในที่ปลอดภัย** (ใช้ตอนกู้ระบบ ไม่ได้ใช้ล็อกอินปกติ)
5. **Region** เลือก **Southeast Asia (Singapore)** — ใกล้ไทยที่สุด เปิดแอปจะเร็วกว่า
6. กด **Create new project** แล้วรอ 1–2 นาทีจนขึ้น **Active**

### 2.2 สร้างตารางฐานข้อมูล (คัดลอก-วาง 2 ไฟล์)
1. เมนูซ้าย กด **SQL Editor** → **New query**
2. เปิดไฟล์ **`supabase/schema.sql`** ด้วย Notepad (Windows) หรือ TextEdit (Mac) → เลือกทั้งหมด → คัดลอก → วางในช่องเว็บ → กด **Run** (หรือ Ctrl+Enter)
   - ต้องขึ้น **Success** สีเขียว · ถ้าขึ้นแดง ให้แคปหน้าจอมาถาม อย่าเดาแก้เอง
3. กด **New query** อีกครั้ง → ทำแบบเดียวกันกับไฟล์ **`supabase/seed_reference_data.sql`** → **Run**
   - ไฟล์นี้ใส่ข้อมูลจริงให้: 5 สาขา, 44 รายการวัตถุดิบ, ระดับสต๊อกต่อรอบรายสาขา, รอบส่งของ, ชื่อ/ที่อยู่/เลขผู้เสียภาษีของทั้ง 2 บริษัท
   - สต๊อกคลังกลางตั้งต้นเป็น **0 ทุกรายการ** ต้องไปนับของจริงแล้วบันทึกเองทีหลัง (ขั้นที่ 5)

> ⚠ รันแค่ 2 ไฟล์นี้ · ไฟล์ใน `supabase/migrations/` **ไม่ต้องรัน** — มีไว้สำหรับคนที่เคยติดตั้งเวอร์ชันเก่าไปแล้วเท่านั้น ติดตั้งใหม่มีครบอยู่ใน `schema.sql` แล้ว

#### ถ้าขึ้น `ERROR: 42710: type "user_role" already exists`

**ไม่ใช่ของเสีย** — แปลว่า `schema.sql` **รันสำเร็จไปแล้วรอบหนึ่ง** แล้วกำลังรันซ้ำอีกรอบ (ตารางสร้างซ้ำไม่ได้)

เช็คให้ชัวร์ก่อนว่าครบจริง — วางบรรทัดนี้ใน SQL Editor แล้ว Run:

```sql
select count(*) as จำนวนตาราง from information_schema.tables
where table_schema = 'public' and table_type = 'BASE TABLE';
```

- ได้ **26** → ครบแล้ว ข้ามไปรัน `seed_reference_data.sql` ต่อได้เลย ไม่ต้องรัน `schema.sql` อีก
- ได้น้อยกว่า 26 หรืออยากเริ่มใหม่ให้สะอาด → รัน **`supabase/reset.sql`** หนึ่งครั้ง (ล้างทิ้งทั้งหมด)
  แล้วค่อยรัน `schema.sql` กับ `seed_reference_data.sql` ใหม่ตามลำดับ

> `reset.sql` ลบเฉพาะตารางข้อมูล **ไม่ลบบัญชีล็อกอิน** ที่สร้างไว้ใน Authentication ·
> ⚠ ห้ามรัน `reset.sql` หลังเริ่มใช้งานจริงแล้ว ยอดขาย/เวลาเข้างาน/เงินเดือนจะหายหมด กู้ไม่ได้

### 2.3 ติดตั้งตัวช่วยจัดการบัญชี (Edge Function)
การสร้างบัญชี/เปลี่ยนรหัสผ่าน ต้องใช้กุญแจระดับผู้ดูแล ซึ่ง**ห้ามเก็บไว้ในหน้าเว็บเด็ดขาด** (ใครกดดูโค้ดหน้าเว็บก็เจอ แล้วแก้ฐานข้อมูลได้ทุกอย่าง) จึงต้องเอาไปวางไว้ฝั่งเซิร์ฟเวอร์ของ Supabase

1. เมนูซ้าย กด **Edge Functions**
2. กด **Deploy a new function** → เลือก **Via Editor**
3. ช่องชื่อฟังก์ชัน ใส่ **`admin-users`** — ⚠ ต้องสะกดตรงนี้เป๊ะ ตัวเล็กทั้งหมด มีขีดกลาง ไม่งั้นแอปเรียกไม่เจอ
4. เปิดไฟล์ **`supabase/functions/admin-users/index.ts`** → คัดลอกทั้งไฟล์ → **ลบโค้ดตัวอย่างในช่องแก้ไขให้หมด** แล้ววางทับ
5. กด **Deploy function** → รอ 10–30 วินาที จนขึ้นสถานะเขียว

> ไม่ต้องตั้งค่ากุญแจอะไรเพิ่ม — Supabase ใส่ให้เองอัตโนมัติ · ฟังก์ชันนี้เช็คทุกครั้งว่าคนเรียกเป็น "เจ้าของ" จริงก่อนทำงาน คนอื่นเรียกไม่ได้

### 2.4 สร้างบัญชีเจ้าของ (บัญชีแรก ต้องทำมือครั้งเดียว)
1. เมนูซ้าย **Authentication** → **Users** → **Add user** → **Create new user**
2. ช่อง **Email** ใส่ **`owner@nomicha.local`**
   - นี่คือชื่อผู้ใช้ `owner` ต่อท้ายด้วยโดเมนที่ระบบใช้ภายใน · **ไม่มีการส่งอีเมลจริง** อีเมลนี้ไม่ต้องมีอยู่จริง
3. **Password** ตั้งรหัสที่จำได้ (อย่างน้อย 6 ตัว) — นี่คือรหัสที่จะใช้ล็อกอินเข้าแอปจริง
4. ติ๊ก **Auto Confirm User** → กด **Create user**
5. ในตารางรายชื่อ **คัดลอก UID** ของบัญชีนี้ (ข้อความยาว ๆ แบบ `a1b2c3d4-5e6f-...`)
6. กลับไป **SQL Editor** → **New query** → วางคำสั่งนี้ **แล้วแทนที่ 3 จุดในวงเล็บด้วยของจริง** → **Run**

```sql
insert into employees (id, username, name, first_name, last_name, role, base_salary, days_off_quota)
values ('(วาง UID ที่คัดลอกมา)', 'owner', 'เจ้าของ', '(ชื่อจริง)', '(นามสกุล)', 'owner', 0, 0);
```

### 2.5 คัดลอกค่าเชื่อมต่อ 2 ตัว (ใช้ในขั้นที่ 3)
1. เมนูซ้าย **Project Settings** (รูปเฟือง) → **API Keys**
2. คัดลอกเก็บไว้ 2 ค่า **วางในไฟล์ Notepad พักไว้ก่อน** เดี๋ยวต้องใช้:
   - **Project URL** — หน้าตาแบบ `https://abcdefgh.supabase.co`
   - **Publishable key** (ขึ้นต้นด้วย `sb_publishable_...`) — ถ้าโปรเจกต์ยังใช้ชื่อเดิม จะเห็นเป็น **anon public** แทน ใช้ตัวนั้นได้เหมือนกัน

> ⚠ **ห้ามคัดลอก "Secret key" หรือ "service_role" ไปใช้ในขั้นที่ 3 เด็ดขาด** — สองตัวนั้นข้ามระบบสิทธิ์ทั้งหมด ถ้าหลุดไปอยู่ในหน้าเว็บ ใครก็แก้ฐานข้อมูลได้ · ตัวที่ต้องใช้คือตัวที่มีคำว่า **publishable** หรือ **anon** เท่านั้น

## ขั้นที่ 3 — Vercel (เปิดเป็นเว็บจริง)

### 3.1 สมัครและเชื่อมกับ GitHub
1. ไปที่ https://vercel.com → **Sign Up** → เลือก **Continue with GitHub**
2. เลือกแบบ **Hobby** (ฟรี) → ใส่ชื่อตัวเองตามที่ถาม

### 3.2 สร้างโปรเจกต์
1. กด **Add New…** → **Project**
2. หา `nomicha-app` ในรายการ → กด **Import**
   - ถ้าไม่เห็น: กด **Adjust GitHub App Permissions** แล้วอนุญาตให้ Vercel เห็น repo นี้
3. ช่อง **Framework Preset** ต้องขึ้นว่า **Vite** เอง — ถ้าขึ้นแบบอื่นให้เลือกเป็น Vite
4. กางหัวข้อ **Environment Variables** แล้วใส่ 2 ตัวที่คัดลอกไว้จากข้อ 2.5:

| Name (พิมพ์ให้ตรงเป๊ะ ตัวใหญ่ทั้งหมด) | Value |
|---|---|
| `VITE_SUPABASE_URL` | Project URL ที่คัดลอกมา |
| `VITE_SUPABASE_ANON_KEY` | Publishable key (หรือ anon public) ที่คัดลอกมา |

5. กด **Deploy** → รอ 1–2 นาที
6. เสร็จแล้วจะได้ลิงก์แบบ `https://nomicha-app.vercel.app` — **นี่คือลิงก์ที่พนักงานทุกคนจะใช้** เก็บไว้ส่งให้ทีม

> **ถ้าเปิดแล้วขึ้น "ยังต่อฐานข้อมูลไม่ได้"** แปลว่าค่า 2 ตัวในข้อ 4 ผิดหรือขาด — แก้ที่ **Settings → Environment Variables** แล้วต้องกด **Deployments → จุด 3 จุดของรายการบนสุด → Redeploy** ด้วย (แก้ค่าเฉย ๆ ไม่มีผลจนกว่าจะ deploy ใหม่)

## ขั้นที่ 4 — สร้างบัญชีที่เหลือในแอป (ไม่ต้องแตะ Supabase แล้ว)

1. เปิดลิงก์ Vercel ที่ได้ → ล็อกอินด้วยชื่อผู้ใช้ **`owner`** กับรหัสที่ตั้งไว้ในข้อ 2.4
2. ไปแท็บ **ตั้งค่า** → การ์ด **จัดการสาขา**
3. แตะชื่อสาขาทีละสาขา → กรอก **ชื่อผู้ใช้ / รหัสผ่าน / ชื่อเล่น / ชื่อจริง / นามสกุล** → กด **สร้างบัญชี**
4. บล็อกเดิมที่กางอยู่ กรอกที่เหลือให้ครบ: **เลขบัตรประชาชน · เงินเดือน · วันหยุด/เดือน · ค่าเช่าสาขา · เวลาเข้างาน-ปิดร้าน · ผ่อนผันสาย · พิกัด/รัศมี**
5. ทำแบบเดียวกันกับบล็อก **หัวหน้า** (ใส่เงินเดือนฐาน เงินส่งของ ค่าเช่าคลังกลางด้วย)

**ชื่อผู้ใช้ที่แนะนำ** (ต้องเป็นอังกฤษตัวเล็ก/ตัวเลข ห้ามภาษาไทย ห้ามเว้นวรรค):

| สาขา/ตำแหน่ง | ชื่อผู้ใช้ |
|---|---|
| เหล่านาดี | `laonadee` |
| บ้านหว้า | `banwa` |
| หนองหลุบ | `nonglub` |
| เขาสวนกวาง | `khaosuankwang` |
| บัณฑิต | `bandit` |
| หัวหน้า | `huana` |

> **ตั้งชื่อตามสาขา ไม่ใช่ตามคน** เพราะ 1 สาขา = 1 บัญชี · เปลี่ยนคนทำงานให้แก้ชื่อ-นามสกุล-เลขบัตรในบัญชีเดิม ชื่อผู้ใช้กับรหัสเดิมใช้ต่อได้เลย

> **เวลาทำงานค่าเริ่มต้นคือ 08:00–18:00 ไม่ผ่อนผัน ทุกสาขา** — ถ้าจริง ๆ ไม่ใช่แบบนี้ **ต้องแก้ก่อนเริ่มใช้งาน** ไม่งั้นระบบจะหักเงินคนผิด

## ขั้นที่ 5 — นับสต๊อกคลังกลางจริงครั้งแรก

สต๊อกคลังกลางตั้งต้นเป็น 0 ทุกรายการ ต้องนับของจริงแล้วบันทึกเข้าไป (ตามหลักการข้อ 17.5 ในสเปก)
ไป **SQL Editor** → รันคำสั่งนี้ทีละรายการ (ดูเลข id ของแต่ละรายการได้ในตาราง `stock_items`):

```sql
update warehouse_stock set case_qty=(จำนวนลังเต็ม), loose_qty=(จำนวนชิ้นเศษ) where item_id=(เลข id);
```

## ขั้นที่ 6 — ทดสอบก่อนใช้จริง

ทำตามนี้ให้ครบก่อนบอกทีมให้เริ่มใช้:

1. ล็อกอินด้วยชื่อผู้ใช้ของสาขาเหล่านาดี → ต้องเห็นหน้าลงเวลา
2. **ไปยืนที่หน้าร้านจริงแล้วลองกดลงเวลา** — เช็คว่ารัศมี 100 เมตรพอไหม (ร้านในตึก/ห้างอาจต้องเพิ่มเป็น 150–200 ม.) ⚠ ข้อนี้สำคัญที่สุด ถ้าลงเวลาไม่ได้ พนักงานทำงานไม่ได้เลย
3. นับแก้วก่อนขาย → ปิดยอด → ส่งยอด ให้ครบ 1 รอบ
4. ล็อกอินเป็นเจ้าของ → เช็คว่ายอดที่พนักงานส่งขึ้นมาถูกต้อง
5. ลองปริ้นสลิปเงินเดือน 1 ใบ → เช็คว่าชื่อ-นามสกุล-เลขบัตร-ชื่อบริษัทขึ้นครบ

## สถานะงาน ณ ตอนนี้ (5 ก.ย. 69 — อัปเดตรอบ "ทำต่อให้เสร็จ")

**เสร็จแล้ว:**
- ฐานข้อมูลครบ (schema.sql ผ่านการทดสอบจริงด้วย Postgres แล้ว รวม Row Level Security ทั้ง 3 บทบาท — ตรวจซ้ำอีกรอบหลังแก้ policy หลายจุด ดูหัวข้อ "แก้ไข RLS" ด้านล่าง)
- ข้อมูลอ้างอิงจริงครบ (5 สาขา/44 รายการวัตถุดิบ/220 ระดับ par/รอบส่งของ)
- หน้าพนักงานสาขา ครบ 3 แท็บ (หน้าแรก: ลงเวลา+นับแก้ว+จองวันหยุด+ส่งเงินสด+เช็ควัตถุดิบนำเข้า / ปิดยอด / ของฉัน: สรุปเงินเดือน+ขอเบิกเงิน-เงินกู้+ประวัติลงเวลา) ต่อฐานข้อมูลจริงแล้ว
- หน้าหัวหน้า ครบ 5 แท็บ (ตารางงาน+จองวันหยุด / รอบส่งของ+เช็คสต๊อกคลังกลาง+บันทึกบิลซื้อ / ขายนอกสาขา / ยอดส่งเงิน / ลงเวลาไปแทนสาขา)
- หน้าเจ้าของ ครบ 7 แท็บ (ภาพรวมวันนี้ / สรุปยอดสาขา-แก้ย้อนหลัง / ตารางงาน / สต๊อก / เงินเดือน / กำไรขาดทุน / ตั้งค่า)
- เอกสารพิมพ์ครบทั้ง 5 แบบ (`src/print.js`): สลิปเงินเดือนพนักงานสาขา, สลิปเงินเดือนหัวหน้า, ใบส่งของ (รายรอบ), บิลขายนอกสาขา+สรุปทั้งเดือน, สรุปการส่งของทั้งเดือน (ทุกสาขา) — ดึงชื่อ/ที่อยู่/เลขผู้เสียภาษีจากตาราง `companies` จริง (ไม่ใช่ฝังในโค้ดเหมือนต้นแบบ) ปุ่มปริ้นอยู่ในหน้าพนักงาน/หัวหน้า/เจ้าของแล้ว
- สูตรคำนวณ (`src/calc.js`) ตรวจเทียบกับต้นแบบด้วยข้อมูลจริง (สาขาเหล่านาดี) แล้วตรงกันทุกบิตทั้ง payrollFor/branchPL/payrollForRelief/warehousePL

**แก้ไข RLS (Row Level Security) รอบนี้ — พบจากการไล่โค้ดจริงว่าใครต้องเข้าถึงอะไรบ้าง แล้วพิสูจน์ด้วย Postgres จริงทุกจุด:**
- `advances.branch_id` เดิมเป็น `not null` ทำให้หัวหน้า (ไม่มีสาขาเดียว) ขอเบิก/เงินกู้ไม่ได้เลย → เปลี่ยนเป็น nullable
- `day_offs`/`relief_day_offs` เดิมให้อ่านได้เฉพาะหัวหน้า/เจ้าของ/สาขาตัวเอง แต่ปฏิทินจองวันหยุดของพนักงานต้องเห็นการจองข้ามสาขาด้วย (กันจองชนกัน) → แยกเป็นนโยบายอ่านได้ทุกคน + เขียนได้เฉพาะสาขาตัวเอง
- `cash_remittances` เดิมให้เขียนได้เฉพาะหัวหน้า/เจ้าของ ทั้งที่พนักงานสาขาต้องกดส่งเงินสดเอง → เพิ่มสิทธิ์เขียนให้สาขาตัวเองด้วย (**ตรวจยืนยันแล้วด้วย Postgres จริงว่าพนักงานส่งเงินสดของสาขาตัวเองได้ และส่งของสาขาอื่นไม่ได้**)
- `remit_loan_offsets` แก้แบบเดียวกัน (พนักงานเลือกเก็บเงินสดไว้เป็นเงินกู้แทนได้เอง) — ตรวจยืนยันแล้ว
- `employees` เดิมหัวหน้าอ่านรายชื่อพนักงานคนอื่นไม่ได้เลย (จำเป็นสำหรับหน้าเงินเดือน/ตารางงานข้ามสาขา) → เพิ่มนโยบาย `relief_read_employees`

**รอบตรวจทั้งระบบ (5 ก.ย. 69) — ไล่เทียบกับต้นแบบทีละหน้า + ตรวจการเชื่อมโยงตัวเลขทุกจุด พบและแก้บั๊กจริง 11 จุด:**

เขียนชุดทดสอบที่ "รันหน้าจอจริงทั้ง 3 บทบาททุกแท็บด้วยข้อมูลจำลอง" ไว้ที่ `test/` (สั่ง `npm test`) — ตรวจทั้งว่าไม่มี error, ไม่มี NaN/undefined โผล่บนจอ และตัวเลขเชื่อมโยงกันถูกต้อง 17 ชุด ผ่านหมดทั้งเขตเวลาไทย/UTC/สหรัฐฯ

1. **เขตเวลา — วันที่เลื่อนไป 1 วันทั้งระบบเมื่อใช้งานที่ไทย** (ร้ายแรงที่สุด) โค้ด 3 จุดใช้ `toISOString()` ซึ่งแปลงกลับเป็นเวลา UTC ก่อน (เที่ยงคืนไทย = 17:00 ของเมื่อวานตามเวลา UTC) ทำให้ **วันครบกำหนดหักเงินกู้เพี้ยนไปเป็นวันที่ 4/19 แทนที่จะเป็น 5/20** (เงินกู้ถูกนับว่าหักคืนแล้วเร็วไป 1 วัน ยอดหักไปโผล่ผิดงวด), ปฏิทินจองวันหยุดเลื่อนทั้งแถบ และตารางสรุปยอดของเจ้าของดึงข้อมูลผิดวัน — แก้เป็น `isoDate()` (วันที่ตามเวลาเครื่อง) เหมือนต้นแบบทุกจุด
2. **พนักงานเห็นผลตรวจสอบเงินขาด/เกิน** หลังกดส่งยอด ซึ่งผิดกติกาที่ตกลงกันไว้ว่าพนักงานต้องไม่เห็น ให้เจ้าของตรวจฝ่ายเดียว — ตัดออกแล้ว (ต้นแบบขึ้นแค่ "ส่งยอดเรียบร้อย")
3. **พิมพ์ตัวเลขมีคอมมาแล้วกลายเป็น 0 เงียบ ๆ** — พิมพ์ "1,250" ในช่องเงินสดจะบันทึกเป็น 0 ทันที (ยอดขาย/เงินสด/เงินเดือนเพี้ยนทั้งสายโดยไม่มีใครรู้) ต้นแบบมีตัวกรอง `numIn()` แก้เรื่องนี้ไว้แล้วแต่ไม่ได้พอร์ตมา — เพิ่มแล้วทุกช่องกรอก และช่องตั้งค่า (ราคา/ค่าเช่า/ระดับสต๊อก) พิมพ์ผิดจะคงค่าเดิมไว้แทนที่จะกลายเป็น 0
4. **เงินเดือนฐานในหน้าพนักงานเป็น 0 เสมอ** — อ่านจากตาราง `branches` ซึ่งไม่มีคอลัมน์นี้ (อยู่ที่ `employees`) พนักงานเห็นเงินเดือนต่ำกว่าจริง ~9,000 บาท และสลิปที่ปริ้นก็ผิด ขณะที่ตารางของเจ้าของถูก → เลขสองหน้าจอไม่ตรงกัน
5. **หัวหน้าส่งยอดแทนสาขาได้ทั้งที่ยังไม่นับแก้วก่อนขาย** → ยอดแก้ววันนั้นกลายเป็น 0 (หัวหน้าเสียค่าแก้ว) และเงิน "เกิน" ก้อนโตปลอม ๆ ลามไปกำไร/ขาดทุนทั้งเดือน — บังคับนับแก้วก่อนเหมือนฝั่งพนักงานแล้ว
6. **เก็บเงินสดไว้เป็นเงินกู้แทนการส่ง — ยอดที่เคยเก็บไว้ถูกล้างทิ้ง** โค้ดล้างเป็น 0 ก่อนแล้วค่อยบวกใหม่ ทำให้พนักงานกลายเป็นค้างส่งเงินสดเกินจริง (จ่ายซ้ำ) — แก้เป็นบวกสะสมตามต้นแบบ
7. **ยอด "เงินสดค้างที่สาขา" ที่เจ้าของเห็นไม่ตรงกับที่พนักงานเห็น** — ฝั่งเจ้าของไม่หักยอดที่พนักงานขอเก็บไว้เป็นเงินกู้ และดูเฉพาะเดือนปัจจุบัน (ถ้าส่งเงินครั้งล่าสุดเป็นเดือนก่อน วันค้างจะหายไป) แก้ให้ใช้สูตร/ตัวหักชุดเดียวกันทั้ง 3 หน้าจอ
8. **หัวหน้าปิดยอดแทนสาขาแล้วสต๊อก "แถวแก้ว" เป็นของเมื่อวาน** (ลอกมาทั้งก้อน) กระทบรายการที่ต้องจัดส่งรอบถัดไป — แก้ให้คิดจากยอดที่นับวันนี้เสมอ ส่วนวัตถุดิบอื่นคงยอดเมื่อวานไว้ตามเดิม (วันไปแทนไม่ต้องนับสต๊อก)
9. **หน้าสต๊อกรายสาขาของเจ้าของไม่ยกยอดวันก่อนหน้ามา** — ก่อนสาขาปิดยอดของวันนี้ ช่อง "ต้องเติม" กลายเป็นเท่ากับระดับที่ต้องมีเต็มจำนวนทุกรายการ (เจ้าของอ่านแล้วสั่งของเกิน) และยอด "ใช้ไป" ที่คร่อมวันว่างหายไปทั้งก้อน — เพิ่มการยกยอดตามต้นแบบ (`stockAt`)
10. **เงินสดค้างส่งดูย้อนหลังแค่ 40 วัน** ถ้าค้างส่งนานกว่านั้นยอดจะขาดหายเงียบ ๆ — เปลี่ยนเป็นไล่ตั้งแต่วันที่ส่งเงินครั้งล่าสุดจริง
11. **กดปุ่มส่งยอดรัว ๆ บนมือถือแล้วหน้าจอค้าง** (ต้นแบบเคยเจอและแก้ไว้แล้ว) — เพิ่มการกันไว้ทั้งฝั่งพนักงานและหัวหน้า

**ของที่เพิ่มให้ตรงกับต้นแบบในรอบนี้:** การ์ด "เงินที่จะได้รับ" ในหน้าพนักงาน (แจงว่าหักเงินกู้/เงินเบิก/เงินสดนำกลับก่อน อย่างละเท่าไร — ก้อนที่เถียงกันบ่อยที่สุด), ข้อความพรีวิวดอกเบี้ย/ยอดค้างตอนขอเก็บเงินสดไว้เป็นเงินกู้, ปุ่ม "ส่งออกสลิปทุกคน" ในหน้าเงินเดือนของเจ้าของ, ปุ่มยืนยัน "ลูกค้าโอนแล้ว" ของบิลขายนอกสาขา, คอลัมน์ผู้ออกบิล, การ์ดสาขาในภาพรวมวันนี้กดแล้วไปหน้าสรุปยอดของสาขานั้นได้, ประวัติลงเวลาในหน้า "ของฉัน" กรองเฉพาะวันที่ตัวเองทำ (เดิมโชว์วันที่หัวหน้ามาแทนด้วย ทำให้เข้าใจผิดว่าได้ค่าแก้ววันนั้น)

**ปรับให้โค้ดสั้นลง/ไม่ซ้ำซ้อน:** รวมฟอร์มปิดยอด+การตรวจค่า+การบันทึกของพนักงานกับหัวหน้าเป็นไฟล์เดียว (`src/close.js` — เดิมเขียนซ้ำสองที่แล้วเพี้ยนกันจริงตามข้อ 5 และ 8), รวมการคำนวณเงินเดือนของแท็บ "เงินเดือน" กับ "กำไร/ขาดทุน" เป็นชุดเดียว (เดิมคำนวณแยกกัน ถ้าแก้สูตรที่เดียวลืมอีกที่ ตัวเลขสองหน้าจะไม่ตรงกันทันที), รวมการโหลดข้อมูลอ้างอิงเป็น `src/refs.js` — ตรวจด้วยเครื่องมือแล้วว่าไม่เหลือบล็อกโค้ดซ้ำกันตั้งแต่ 4 บรรทัดขึ้นไปเลย และไม่เหลือฟังก์ชัน/ตัวแปร/ค่าตั้งค่าที่ประกาศไว้แล้วไม่มีใครใช้

**ทำครบทุกอย่างที่เคยตัดทอนไว้แล้ว (5 ก.ย. 69 รอบสุดท้าย):**
- **แท็บ "ตารางงาน" ของเจ้าของ** — ดูรายเดือนว่าใครจองหยุดวันไหน หัวหน้าต้องไปแทนสาขาไหน วันไหนเป็นวันส่งของ พร้อมสรุปโควตาวันหยุดที่จองแล้วของทุกคน
- **บังคับ GPS ตอนลงเวลา** (ดูหัวข้อด้านบน)
- **ย้ายกติกาจ่าย/หักมาไว้ในหน้าตั้งค่า** — ค่าแก้ว/บาทต่อนาทีที่สาย/ค่าปรับลืมลงเวลา/ค่าปรับหยุดเกินโควตา/เบี้ยขยัน/ค่าทำงานวันหยุด/ราคาแก้ว/จำนวนแก้วต่อแถว แก้ได้เองทั้งหมด ไม่ต้องแก้โค้ดแล้ว
- **เจ้าของออกบิลขายนอกสาขาได้เอง** (เดิมต้องไปออกที่หน้าหัวหน้า) และ**แก้ไข/ยกเลิกบิลย้อนหลังได้** — ระบบคืน/ตัดสต๊อกคลังกลางตามส่วนต่างให้อัตโนมัติ พร้อมจดประวัติว่าใครแก้อะไร
- **แก้รอบส่งของได้ในหน้าตั้งค่า** — เปลี่ยนชื่อรอบ วันในสัปดาห์ และติ๊กว่ารอบนั้นส่งสาขาไหนบ้าง (เดิมต้องแก้ผ่าน SQL)
- **การ์ดประวัติการแก้ไขย้อนหลัง** ท้ายหน้าสรุปยอดสาขา — เห็นครบว่าแก้ยอดวันไหน แก้อะไร เมื่อไร
- **ตัวกรอง "เฉพาะที่ต้องเติม"** ในหน้าสต๊อก และ **ตัวเลข "ใช้จริง 7 วันล่าสุด"** ข้างช่องตั้งระดับสต๊อกต่อรอบ (กันตั้งมั่วจนสั่งของเกิน/ขาด)
- **ข้อความบอกบริบทครบเหมือนต้นแบบ** — ปฏิทินจองวันหยุดบอกชื่อสาขาที่จองไปแล้วและชื่อรอบส่งของ, ตารางไปแทนบอกชื่อคนที่หยุด, การ์ดเงินสดค้างส่งบอกว่ารอบถัดไปวันไหน

**เวลาทำงานรายสาขา + เวลาไทย (เพิ่ม 5 ก.ย. 69):**

กติกาหักมาสาย/ปิดไว และเบี้ยขยัน **ใช้งานได้จริงแล้ว** — เพิ่มเวลาทำงานแยกรายสาขา (เข้างาน / ปิดร้าน / ผ่อนผันกี่นาที) ตั้งค่าได้ที่ **หน้าเจ้าของ → ตั้งค่า → การ์ด "พิกัดลงเวลา + เวลาทำงาน"** ซึ่งอยู่การ์ดเดียวกับพิกัด GPS ของร้าน (เดิมพิกัดต้องแก้ผ่าน SQL อย่างเดียว ตอนนี้แก้ในหน้าเว็บได้แล้ว)

- ตอนพนักงานกดลงเวลาเข้า ระบบเทียบกับ "เข้างาน" ของสาขานั้น เกินที่ผ่อนผันไว้ = นาทีสาย · กดลงเวลาออกก่อน "ปิดร้าน" = ปิดไว · **หักนาทีละ 1 บาท** และถ้าสาย+ปิดไวรวมกันทั้งเดือนเกิน 250 นาที **เบี้ยขยันเดือนนั้นเป็น 0** (ตามกติกาเดิม)
- **ต้องลงเวลาให้ครบทั้งเข้าและออก — ลืมหัก 40 บาท/ครั้ง** นับทั้งกรณีลืมกดเข้า ลืมกดออก และเปิดร้านขายทั้งวันแต่ไม่ได้ลงเวลาเลย · นับเฉพาะวันที่ผ่านไปแล้ว (วันนี้ยังกดลงเวลาออกได้อยู่ ยังไม่ถือว่าลืม) · หน้าพนักงานขึ้นเตือน "อย่าลืมกดลงเวลาออกก่อนกลับ" ไว้ตลอดหลังลงเวลาเข้า
- **หัวหน้าตอนไปทำแทนสาขา ไม่หักมาสาย/ปิดไว** (ไปทำแทนหลายสาขาคนละเวลา บางวันต้องไปส่งของก่อน) แต่ยังต้องลงเวลาให้ครบเข้า-ออก ลืมยังหัก 40 บาท/ครั้งเหมือนกัน
- ตัวเลขนาทีถูกคิดและเก็บ **ตอนกดลงเวลา** ไม่ได้คิดสดตอนทำเงินเดือน — เจ้าของแก้เวลาทำงานทีหลังจึง **ไม่มีผลย้อนหลัง** กับเดือนที่จ่ายไปแล้ว (หลักการเดียวกับค่าเช่า)
- ค่าเริ่มต้นคือ **08:00–18:00 ไม่ผ่อนผัน** ทุกสาขา — ถ้าจริง ๆ ไม่ใช่แบบนี้ ให้ไปแก้ในหน้าตั้งค่าก่อนเริ่มใช้งาน ไม่งั้นจะหักคนผิด
- **ลงเวลาได้เฉพาะตอนอยู่ที่ร้านจริง** — ทุกครั้งที่กดลงเวลาเข้า/ออก ระบบขอตำแหน่งจากเครื่องแล้ววัดระยะถึงพิกัดร้าน ถ้าเกินรัศมีที่ตั้งไว้จะลงไม่ได้ พร้อมบอกว่าอยู่ห่างกี่เมตร · ระยะที่วัดได้ถูกเก็บไว้ในแต่ละแถวลงเวลา (`in_distance_m`/`out_distance_m`) เจ้าของตรวจย้อนหลังได้ว่าลงเวลาจากที่ร้านจริง
- **ทั้งระบบยึดเวลาไทย (Asia/Bangkok) เป็นหลัก** ไม่ใช่เวลาของเครื่อง/มือถือที่เปิดใช้ — ทั้ง "วันนี้คือวันไหน" และ "ตอนนี้กี่โมง" ถ้ามือถือพนักงานตั้งเขตเวลาผิด หรือเจ้าของเปิดดูจากต่างประเทศ ยอดก็ยังลงวันถูกและเวลาเข้า-ออกยังเทียบกับเวลาร้านได้ถูกต้อง (ทดสอบแล้วด้วยเครื่องที่ตั้งเขตเวลาไทย/UTC/สหรัฐฯ/นิวซีแลนด์ ได้ผลตรงกันหมด)

> **ถ้าเคยรัน `schema.sql` เวอร์ชันก่อนหน้าไปแล้ว** ต้องรัน `supabase/migrations/001_work_hours.sql` เพิ่มใน SQL Editor หนึ่งครั้ง (เพิ่มเวลาทำงาน 3 คอลัมน์ให้ `branches` + ระยะห่าง 2 คอลัมน์ให้ `clock_records`) — ถ้าเพิ่งติดตั้งใหม่ ไม่ต้องรัน มีอยู่ใน `schema.sql` แล้ว

> ⚠ **เรื่องที่ต้องรู้ก่อนเปิดใช้ GPS จริง** — ถ้าพนักงานไม่กดอนุญาต "ตำแหน่งที่ตั้ง" ให้เว็บ หรือมือถือจับ GPS ไม่ได้ (อยู่ในตึก สัญญาณอ่อน) **จะลงเวลาไม่ได้เลย** ระบบไม่มีทางลัดให้ข้าม — เป็นไปตามที่สั่งไว้ว่า "ลงเวลาได้ในระยะเท่านั้น" · แนะนำให้ลองจริงที่หน้าร้านทุกสาขาก่อนเริ่มใช้ ว่ารัศมี 100 เมตรพอไหม (ร้านในตึก/ห้างอาจต้องเพิ่มเป็น 150–200 ม.) · ถ้าเจอปัญหาหน้างานบ่อย บอกได้ ผมทำทางออกให้ เช่นให้กดลงเวลาไว้ก่อนแล้วส่งให้เจ้าของอนุมัติทีหลัง
>
> ถ้าสาขาไหน**ยังไม่ได้กรอกพิกัด** ระบบจะยอมให้ลงเวลาไปก่อนพร้อมขึ้นเตือน (ถ้าบล็อกทั้งที่ยังไม่ได้ตั้งค่า ทั้งสาขาจะทำงานไม่ได้เลย) — ข้อมูลพิกัดจริงของทั้ง 5 สาขาใส่มาให้แล้วตั้งแต่ต้น ตรวจดูอีกทีในหน้าตั้งค่าได้

**ล็อกอินด้วยชื่อผู้ใช้ + หน้าจัดการสาขา (เพิ่ม 5 ก.ย. 69 — ตามที่เจ้าของสั่ง):**

- **เปลี่ยนจากอีเมลเป็นชื่อผู้ใช้** — หน้าล็อกอินกรอก "ชื่อผู้ใช้ + รหัสผ่าน" ระบบต่อ `@nomicha.local` ให้เองเบื้องหลัง (Supabase บังคับรูปแบบอีเมล จึงต้องใช้ตัวอักษรอังกฤษ) · บัญชีเก่าที่เคยสร้างด้วยอีเมลยังล็อกอินได้ พิมพ์อีเมลเต็มมาก็รับ
- **หน้า "จัดการสาขา"** ในตั้งค่าของเจ้าของ — แตะชื่อสาขาแล้วกางออก มีครบในที่เดียว: ชื่อผู้ใช้ · รหัสผ่าน · ชื่อเล่น · ชื่อจริง · นามสกุล · เลขบัตรประชาชน · เงินเดือน · วันหยุด · ค่าเช่า · เวลาทำงาน · พิกัดลงเวลา (การ์ด "พนักงาน" กับ "พิกัดลงเวลา + เวลาทำงาน" เดิมถูกยุบรวมมาไว้ที่นี่ทั้งหมด) พร้อมบล็อกของหัวหน้าและเจ้าของ
- **สร้างบัญชี/เปลี่ยนรหัสผ่านได้เองในแอป** — ผ่านตัวช่วย `admin-users` (ดูข้อ 4.1) ไม่ต้องกลับไปที่ Supabase อีก
- **1 สาขา = 1 บัญชี** เปลี่ยนคนทำงานกลางเดือนให้แก้ชื่อ-นามสกุล-เลขบัตรในบัญชีเดิม — **ยอดแก้ว/นาทีสาย/เงินเบิก/เงินเดือนของเดือนนั้นคิดรวมเป็นก้อนของสาขา** ไม่แยกตามชื่อคน (ตามที่เจ้าของเลือกไว้) ยกเว้นวันที่หัวหน้ามาทำแทน ซึ่งยังแยกไปเข้าเงินเดือนหัวหน้าเหมือนเดิม
- **ชื่อจริง/นามสกุล/เลขบัตรประชาชน ขึ้นบนสลิปเงินเดือนแล้ว** และ**หัวกระดาษสลิปเป็นบริษัทนายจ้างจริง** — สลิปพนักงานสาขาขึ้น "บริษัท คาเชน จำกัด" · สลิปหัวหน้าขึ้น "บริษัท เพตั้น จำกัด" พร้อมเลขผู้เสียภาษีและที่อยู่
- **เลขบัตรประชาชนเก็บคนละตารางกับข้อมูลพนักงาน** (`employee_private`) เปิดให้อ่านเฉพาะ**เจ้าของกับเจ้าตัว** — หัวหน้าซึ่งอ่านตารางพนักงานได้ทั้งตาราง **อ่านเลขบัตรของคนอื่นไม่ได้** และเจ้าตัวก็แก้เลขของตัวเองไม่ได้ (เจ้าของแก้อย่างเดียว กันแก้เลขบนสลิปเอง) — ทดสอบยืนยันด้วย PostgreSQL จริงทั้ง 6 กรณีแล้ว
- **นายจ้าง** ตั้งตามที่เจ้าของยืนยัน: หัวหน้า = เพตั้น (`warehouse`) · พนักงานสาขา = คาเชน (`branch_co`) — บัญชีเก่าถูก backfill ให้ในสคริปต์อัปเดต

> **ถ้าเคยรัน `schema.sql` เวอร์ชันก่อนหน้าไปแล้ว** รัน `supabase/migrations/001_work_hours.sql` ซ้ำได้เลยหนึ่งครั้ง (ไฟล์เดิม เพิ่มส่วนใหม่ต่อท้าย รันซ้ำไม่พัง — ทดสอบกับฐานข้อมูลรุ่นเก่าจริงแล้ว) จะได้คอลัมน์ชื่อผู้ใช้/ชื่อจริง/นามสกุล + ตารางเลขบัตร + เติมชื่อผู้ใช้จากอีเมลเดิมให้อัตโนมัติ

**ข้อมูลบริษัทครบแล้ว** — ที่อยู่จดทะเบียนและเลขผู้เสียภาษี 13 หลักของทั้ง 2 บริษัท เจ้าของยืนยันแล้ว (6 ก.ย. 69) เอกสารที่ปริ้นออกไปใช้ยื่นสรรพากรได้จริง

**เหลือ 2 เรื่องที่รอคำตอบเจ้าของ (ไม่บล็อกการเริ่มใช้งาน):**
- "ไม่ลงเวลา" นับยังไงในกรณีพิเศษ — ตอนนี้นับว่า "ลืม" เมื่อลงไม่ครบเข้า-ออกในวันที่ผ่านไปแล้ว ถ้าอยากได้เงื่อนไขอื่นบอกได้
- หัวหน้าลืมลงเวลา ตอนนี้ยังหัก 40 เหมือนพนักงาน (ยกเว้นแค่มาสาย/ปิดไว) ถ้าตั้งใจให้ไม่หักเลย บอกได้ แก้จุดเดียว
